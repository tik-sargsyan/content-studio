Multi-scene cinematic

8.7
Steps
  1. Break the trend into ~6 scenes (Gemini reads the mechanic)
  2. Generate 3 video takes per scene with Veo 3.1, let Gemini pick the best
  3. Stitch scenes, add captions and Lyria music, score against the original
Learnings
  • Our highest-quality method (8.7). About $8 and ~10 min per video.
  • Generating 3 takes per scene and voting is what beats a single take.

Evals

Nothing ships unless it passes the judge. Every clip gets a quick safety check for the AI tells (warped faces, identity flips, a fake-looking real person, the effect not actually happening), then FIVE independent reviewers watch the full video and score it - it only passes if they agree. The judge has hard time limits so it can never hang, skips a reviewer that doesn't answer instead of guessing, and is calibrated to a human (we loosen or tighten it when it's too harsh or too soft). Realism is rewarded; only a real or celebrity likeness gets blocked.

Eval methods

quality.py — the trustworthy judge (current)

Scores: Every generated clip (preset or trend), watched as a full video.

Dimensions
  • Safety gate: 9 instant-fail checks (warping, identity flip, fake real-person, melted hands, garbled text/logo, effect-didn't-happen, flicker...)
  • 5 reviewers (1-10): does the effect land · natural motion · photoreal · want-it-on-my-photo · brand-safe
Learnings
  • The old single judge passed bad clips (a 9.6 with no phone UI); the gate + multiple reviewers catch them.
  • Tuned less-harsh on 2026-06-24 so one grumpy reviewer can't sink a good clip.
  • Restyle + simple motion pass easily; freeze-frame and complex morphs fail.

How: Any safety hit = fail. Else it passes when the average clears the bar and at least 3 of 5 reviewers voted. 180s hard timeout + watchdog so it never hangs; a no-vote is flagged, never counted as 0. Calibrated to a human judge.

auto_eval.py (cinematic scorecard)

Scores: Final generated 6-scene compilation vs the original viral reference video. Used for cinematic / mood-reel / dreamscape replicas.

Dimensions
  • style_match (weight 0.35)
  • hero_visual_clarity (weight 0.25)
  • text_legibility (weight 0.15)
  • brand_safety (weight 0.25)
Learnings
  • LLM-judge noise is +/-0.5 per call on identical input. Don't trust deltas < 1.0.
  • A single weighted total hides single-scene text failures (v12 had broken text on scenes 1/3/5 but global text_legibility scored 10/10 because most scenes were fine) -- this is why text_eval.py exists as a separate gate.

How: Compares the finished video to the original on style, hero clarity, text and brand safety. ≥9 = winner, ≥7 = acceptable, else regenerate.

engine/auto_eval.py

auto_eval_ad.py (ad-craft scorecard)

Scores: A Picsart vertical ad on performance-marketing ad-craft fundamentals. Does NOT penalize divergence from the reference -- an ad may diverge if it sells better.

Dimensions
  • hook_strength (weight 0.30)
  • message_clarity (weight 0.20)
  • brand_presence (weight 0.20)
  • cta_clarity (weight 0.15)
  • pacing_motion (weight 0.10)
  • brand_safety (weight 0.05)
Learnings
  • Screen-record and testimonial ad subtypes are unsolvable by Veo (can't render UI or do lip-synced likeness) -- route to Templates team instead.
  • Brand presence is enforced structurally (PIL-rendered Picsart intro/outro panels + logo watermark) rather than asking Veo to render brand text.

How: Scores an ad on what makes ads work: hook, message, brand, CTA, pacing. ≥8.5 = winner. It rewards selling, not copying the reference.

engine/auto_eval_ad.py

text_eval.py (per-scene text/glyph gate)

Scores: Per-scene first-frame text rendering: extracts a frame from each composed scene clip and validates the top-bar label against the EXPECTED string.

Dimensions
  • text_correct (matches expected string exactly)
  • text_legible (no broken glyphs / smudging)
  • text_centered (centered in top black bar)
  • text_isolated (no other text bleeding from generated video)
  • font_consistent (white Helvetica ~56pt)
  • overall (1-10)
Learnings
  • This is the safety net for the blind spot in auto_eval.py's single weighted text score.
  • Auto-fix only possible when the raw clip (scene_N_raw.mp4) still exists.

How: Checks the on-screen caption on each scene is correct and clean; auto-fixes by re-rendering the text as an overlay.

engine/text_eval.py

auto_regen_per_scene.py (eval-driven regen loop)

Scores: Not an eval itself -- consumes auto_eval.py's per_scene array and regenerates ONLY scenes scoring below threshold, then re-evals.

Dimensions
  • reads per_scene total vs threshold (default 7.0)
Learnings
  • Fixes the global-broadcast regression where a single directive applied to all scenes regressed the good ones.
  • Multi-sample voting can't fix capability gaps -- if Veo can't render legible text, all 3 candidates fail and the vote picks the least-bad.

How: Regenerates only the scenes that scored low, keeps the good ones, then re-scores. Avoids breaking what already works.

engine/auto_regen_per_scene.py

Multi-sample Gemini voting (in v15_pipeline.py / v15_single_shot.py)

Scores: Per-scene candidate selection: generates 3 Veo candidates per scene and has Gemini Vision vote for the best, to cancel LLM-judge noise.

Dimensions
  • Gemini picks best of N candidates per scene
  • per-scene retry with directive only if winner < threshold
Learnings
  • Multi-sample voting is the primary mitigation for the +/-0.5 judge noise.
  • Cost ~$8 per 6-scene compilation (18 Veo Fast + 7 Gemini + 1 Lyria), ~10 min wall-clock.

How: Generates 3 takes per scene and votes for the best, which cancels the AI judge's noise. This is what makes v15 our top scorer (8.7).

preset_pipeline eval (replica vs original)

Scores: Our Higgsfield-preset replica scored AGAINST the original on 4 equal axes.

Dimensions
  • mechanic fidelity (same photo→video transform?)
  • message/virality (same hook/feeling?)
  • visual similarity (subject/setting/camera/lighting/grade)
  • photoreal craft (premium, no uncanny, brand-safe)
Learnings
  • The old standalone eval over-scored off-target replicas (a generic walk got 9.0 while missing the morph).
  • Multi-subject morphs are a capability gap a single i2v pass can't clear — the eval flags this honestly.

How: Sends the original frame + our replica frame to Gemini Vision; returns a 1-10 score + a surgical regen_directive. Drives a regenerate-to-8.5 loop. Correctly refuses to pass a replica that misses the original's mechanic (e.g. a plain walk vs a walk→car morph).
